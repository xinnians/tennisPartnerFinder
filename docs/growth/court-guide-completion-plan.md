## 補完的定義

幫使用者回答：「這座球場在哪裡、我能不能使用、怎麼取得場地、要花多少錢、何時可以去？」

分開衡量兩件事：

1. **目錄查核覆蓋**：既有每筆場地都有處置結果，包含可發布、待外部資訊、限制使用、不適合一般網球指南、疑似重複等；不是把每筆都做成公開頁。
2. **指南決策資訊**：適合公開的指南逐步補足使用資格、租借／現場流程、時間、費用、夜照、入口與異動資訊；來源衝突或未知要清楚標示。

不以篇數或自動測試通過宣稱使用意願／留存改善。真實成效量測仍屬已暫緩的 G01，本計畫不連帶啟動。

### C01 優先缺口

- **民權公園**：一般民眾現場使用／輪流方式、費用；同頁壘球租借按鈕不能當網球預約。
- **青年公園**：網球專頁05:30、頁尾06:00及園區08:00的時間衝突；夜間照明和是否有額外費用。
- **道南、百齡社子岸**：沒有確認租借入口的面號如何使用，且不能把一般費率表當作每面均開放的證據。
- **其餘河濱指南**：逐面確認夜照、開燈方式與夜間可用條件；大佳另釐清7／10號水門資訊衝突。夜照不可由「營業至22:00」推定。
- **網球中心、台北網球場**：雖無pending，也需核對預約／票價及臨時公告。現場資格優惠應附條件，不只放最低價格。

## 每座球場的查核卡

在對應批次紀錄中使用以下欄位；清冊只放狀態、最重要缺口及該紀錄連結，避免多份文件各有不同真相。

| 欄位 | 應記錄內容 |
| --- | --- |
| 識別 | 既有slug／court_id（如有）、正式名稱、別名、城市／行政區、來源對照；不得靠模糊同名直接合併 |
| 資格與現況 | 一般公眾是否可用、學生／會員／社區限制、營運／施工／暫停訊息及公告日期 |
| 場地 | 一般網球／軟網／練習壁／混用、面號與面數、室內外；未知不得猜測 |
| 使用流程 | 現場輪流、櫃檯購票、電話／線上申請、是否需會員、提前多久、付款與取消條件；按人／按面與包場區別 |
| 時間與夜照 | 網球專屬時段、假日差異、燈光可用面號／操作／另計費；與園區時間分開 |
| 費用 | 幣別、按人／面／小時、尖離峰、照明與附加費、優惠適用資格；未取得即pending，最低價不可省略條件 |
| 位置與交通 | 球場座標、入口／水門、同園區左右岸／橋下差異；有歧義保留證據，不靜默改seed |
| 來源證據 | 官方或營運專頁URL、資料發布／修訂日期（如有）、實際查核日、欄位對應、衝突與取捨理由；公開客服可引用，不蒐集私人聯絡資料 |
| 處置 | 查核狀態、發布狀態、待查原因、下一個可執行動作、查核者、最後更新、下次覆核期限 |

來源優先採主管機關／現行營運單位的場地專頁與公告；通用法規和年度資料用於背景及交叉查核。第三方地圖、部落格與社群公開資訊只作線索。新舊官方資訊衝突要判斷適用場地、日期與管理權，不能僅因一頁較新就套用。需網站登入才可查的資訊記錄限制；聯絡營運人員或代送表單仍需明確授權。

## 狀態與發布門檻

**查核狀態**：待查核 → 查核中 → 可發布／待補來源／限制使用／排除／待去重。已發布仍可能「待補資訊」，與發布狀態分開。

**發布狀態**：未發布 → 內容完成 → QA通過 → 已發布；需撤回時另記撤下日期與原因。C03的「61筆處置完成」可以包含有查核證據的待外部資訊；必須同時列出這些未解決筆數，不能宣稱61筆資訊齊全。

發布新指南最低需要：

- 確認是對應的網球設施，位置與城市不混淆；有近期可靠來源確認公眾使用方式／限制及官方查詢管道。
- 不能確認公眾使用資格或球場實際存在者不發布；暫停使用、疑似廢除或同名不同地者先釐清。
- 費率／夜照等尚未查明可明示pending；不寫確定價格或可使用承諾。公園開放、網球可使用、可線上預約分開描述。
- 具名來源與查核日期、入口資訊、未解決項目及出發前應確認的條件齊備。
- 只用已核可台北目錄接開局／訂閱；其他城市公開前先決定CTA與資料契約，不讓指南意外擴大服務範圍。

已發布指南若出現關鍵資格或營運問題，先人工確認證據，再決定更正文案、暫停相關入口或撤下指南；查無來源或404本身不等於球場停業，也不能自動停用資料庫球場。

## 每批執行與驗收

1. 從清冊選定最多10筆及本批既有指南缺口，記錄本批目標和未完成項。
2. 查官方來源，寫查核卡；對來源不足者保留具體阻礙，繼續其他可獨立查核項目。
3. 只將達門檻內容更新至`data/court-guides.json`，重新產生已發布slug/name對照；清冊不進前端bundle。
4. 沿用repo適用的測試與Git發布規則。內容仍需驗證生成頁、來源連結、搜尋／行政區、no-JS、未知頁404及sitemap；新slug逐一確認開局指向正確球場。桌面／390px檢查長文字、console及互動；容量不得逐批自動提高。
5. 有正式球場目錄／migration變更時走獨立資料變更檢查；不得把全台底稿直接交給會停用缺漏球場的seed generator。
6. 必要CI、Git預覽及正式驗收各自記錄；發布成功後更新逐場清冊、批次QA和progress.md。產品成效另記「未取得」或真實觀測，不使用工程驗證代替。

## 進度指標與維護責任

- **台北查核處置**：分別報61筆中的已發布、可發布未部署、待來源、資格限制、排除／待去重及尚未查核；各狀態互斥，發布狀態另外計數。
- **資訊缺口**：現有15篇的顯式pending基準為13篇／14欄；查核時新發現問題可以增加，不為降低數字刪除pending標記。來源衝突、面號疑義另列，不能只數JSON狀態。
- **行政區覆蓋**：列既有目錄筆數／指南篇數；不是人口覆蓋、需求量或實際使用率。
- **全台品質**：562候選中的人工審核、疑義與來源對照獨立統計，不和89筆正式目錄直接相加。86組疑似同址、50筆開放／租借衝突、兩筆金門／連江地址衝突、341筆學校名稱旗標先分批處理；旗標不互斥。
- **維護人**：專案擁有者ian負責內容決策，Codex依核可範圍查核、實作及保存證據；不得自行對外詢價／送報告。
- **更新時機**：每個批次開始、範圍變更、驗收、發布及session結束時更新progress與清冊。換session先讀兩者及最後批次紀錄，不覆蓋歷史研究。
- **再查核期限**：本輪所有已查核場地與公開指南最晚2026-12-08重新查核。未來以實際查核日起90天作完整覆核期限；費率／停用／租借改版消息一旦發現便優先處理，不能等90天。單純改文案不能刷新verifiedAt。
- **排程狀態**：此為人工維護規劃；既有90天提示是build-time，未建立自動查網址、背景查核或通知排程。
