# 第一批規格：G02／G03／G04

日期：2026-09-09。依使用者核可的競品改善清單執行。

## G02 加入說明

登入以加入球局時使用「登入後確認加入方式」，補充：直接加入局中程度符合可直接加入；未填或超出程度會改為申請；審核制待主揪確認。只改文案，不改 RPC、門檻或結果。

## G03 再次開局

- 「我的球局」的本人主揪卡提供「照這局再開」。目前資料中仍可見的歷史／現在球局皆可使用；不額外開放歷史資料讀取。
- 控制器重新從本人 participation 狀態確認來源是 host，不能讓 UI 傳任意物件作為可信來源。未登入、資料未就緒或來源不存在時不開重用表單。
- 開啟既有建局表單，重用可用的台北球場、玩法、缺額與加入模式，保留合法程度範圍、費用／備註供使用者編輯。舊「對拉」映射成現有「練球」。
- 日期不沿用：要求明確選擇新日期／時間；已訂場一律重設為否。顯示提示要求重新確認場地、時間與文字內的舊資訊。
- 本人歷史 view 沒有候選場地陣列，未定案候選局需重新選擇 2–3 座球場與時段，不藉此放寬資料讀取；已定案候選局可沿用實際定案球場。
- 程度不是既有 preset 時，提供「上次程度」選項保存原值，使用者可改選其他 preset。不能悄悄變成不限。
- 不複製成員、聊天、出席、舊局 ID，不自動建立、不自動邀請、不持久儲存他人資料。
- 開啟／送出之間如帳號改變，由現有 auth snapshot 與 surface cleanup 取消；既有建局權限、容量與未來時間驗證仍生效。
- 若已開建局表單，不覆蓋正在編輯的草稿。

## G04 球局分享摘要

- 詳情按鈕改為「複製球局摘要」，保留既有操作識別與錯誤處理。
- 摘要限公開活動欄位：台北日期／時間、球場或候選狀態、玩法、程度、缺額／狀態、場地情境、相容的 `#/session/:id` 連結。
- 不把整個物件序列化，也不含備註、聯絡資料、roster、使用者身分或聊天。舊的只傳 ID 呼叫仍能複製連結。
- 清楚寫「最新名額與場地以連結為準」。已結束／取消／額滿不能寫成可直接報名；未定案候選局不能把第一座候選當成已定場地。
- 複製不等於分享已送出；不新增外部訊息發送，也不虛報來源量測已完成。

## 介面改動與驗收

使用者核可的本批產品變更包含 login 文案、My Sessions 新按鈕、create form 初值／提示及 share 按鈕文字；對應舊遷移文案／介面凍結依本 spec 更新。既有焦點、逃出、雙擊、資料權限與既有 ID/testid 契約保留。

目標流程：登入使用者的我的球局 → 自己的球局「照這局再開」→ 可編輯草稿 → 選新日期時間 → 明確發布 → 新球局；公開詳情 → 複製摘要 → 讀取剪貼簿內容；匿名加入 → 正確登入說明。

驗證涵蓋正常／未定案候選／來源非主揪／帳號切換、原訂場不沿用、任意程度不放寬、公開摘要個資排除及錯誤處理。執行 repo frontend checks、mock 桌面／手機、本機 Supabase 整合與 build，QA 證據更新在進度。
