## 4. G10：逐局分享預覽

### 使用者體驗

1. 主揪或訪客按既有「複製球局摘要」，保留 G04 文字，連結改為 `https://qiuka.tw/s/123`（123 為示意）。
2. 分享平台讀到該局公開資訊。示意標題：`9/12（六）20:00｜青年公園網球場｜雙打`；描述包含程度、當次查詢缺額及「最新名額與場地以連結為準」。
3. 圖片第一版沿用 `/og.png`，不同球局以標題／摘要區分。字數截斷與卡片組合由分享平台決定，不能承諾每個平台外觀完全相同。
4. 使用者點入直接開啟目前的球局詳情，不增加中間確認頁。登入、加入、返回與關閉流程沿用既有行為。

### 技術方案

- `/s/:id` rewrite 到 Vercel Node Function；handler 僅接受 GET／HEAD 與有效正整數 safe ID，不接受任意網址、任意 SQL／select 或重複歧義參數。
- 用匿名／publishable key 讀既有 `session_discovery`，只取 `session_id,court,start_at,play_type,ntrp_min,ntrp_max,slots_remaining,status,venue_type,range_end,decided_at`。不取主揪欄位、備註、費用自由文字、名單、聯絡資訊；不使用 service role 或訪客登入 token。
- HTML 的 title、description、OG 與 canonical 由 server 產生並跳脫動態字串。`og:type=website`，`og:locale=zh_TW`；origin 由部署設定明確提供，不能信任任意 Host header。
- 人與 crawler 收到相同初始 HTML。Function 使用該次 build 產出的 app shell 模板與 hashed assets；預覽、正式環境及本機設定各自一致，不能請求「目前正式首頁」拼裝模板。
- 初始 HTML 放入 minimal 公開摘要與 `/#/session/:id` fallback link；有 JS 時由 boot 前的薄層把路徑用 `replaceState` 正規化為既有 hash，移除 fallback，再啟動原有 route。這不增加網路 redirect，返回鍵不多一頁，且不讓 `/s/:id#tab-me` 回傳前一球局的 metadata。
- 公開摘要模板、讀取 adapter 與回應函式可分別測試；Node server 模組不得進入 browser import graph。分享文字與 OG 共用適合的純格式函式，不匯入整個 controller。
- 第一版 HTML 不設 CDN 內容快取，回應 `Cache-Control: no-store`，避免本站快取延長下架資料曝光；平台自身的卡片快取仍無法保證即時更新。上線前量測 handler 延遲與請求負擔，日後如需 CDN TTL 另訂到期邊界，不自行更改。
- Supabase 請求設 2 秒 timeout，不在同次請求無限重試。錯誤回應不帶原始 API body／設定值。新增函式的環境可用性與 template 打包需在第一個工程檢查點實證。
- 球局頁 `noindex`，不列入 sitemap；讓分享 crawler 可取 HTML，不把 robots 當資料權限機制。

### 狀態與驗收

| 情況 | 分享 HTTP 與使用者結果 |
| --- | --- |
| 公開 open／full | 200；正確台北日期時間、程度與缺額／額滿；點入重讀最新資料 |
| 未定案候選局 | 不把第一候選當定案球場；顯示候選未定與時間範圍 |
| 已定案候選局 | 顯示定案場地，沿用「訂場待確認」語意，不宣稱已訂場 |
| 查無公開 row | 404＋中性說明、找其他球局入口；不區分不存在、取消或過期 |
| 上游逾時／失敗 | 503＋暫時讀取失敗與既有詳情入口；不誤報查無球局，不快取 |
| 無效 ID／不支援 method | 404／405；不發 DB 請求 |
| 複製舊局或舊推播連結 | 既有 hash 仍可進入原有流程；下架時顯示原有 empty sheet |

HEAD 的 status／headers 與 GET 一致而無 body。測試覆蓋 HTML injection、非台北／下架資料不可見、過期切換、分享中缺額改變、OAuth 往返、重整／返回、不載入 JS 的 metadata，以及 G04 真實剪貼簿。實際 LINE／Facebook 卡片另記平台與查核時間；不代發群組訊息。必要時由維護者自行貼至自己的測試對話，未實測前不寫「平台相容已驗證」。

## 5. G09：三座球場指南

### 選點與本輪查核

本輪選點依資料可得性與不同使用情境，不聲稱已有主揪或球局供給證據。

| 建議球場／既有 slug | 選擇理由 | 已發現的內容限制 |
| --- | --- | --- |
| 青年公園／`youth-park` | 市區公園，與河濱及專用場館形成不同情境 | 官方 VBS 頁明載委外經營、租借需洽營運單位；舊研究「VBS 訂場」不能照搬。頁面一般費用欄不能據以宣稱網球免費 |
| 彩虹河濱／`rainbow-riverside` | 官方明列可預約與現場輪流的不同場地 | 總規格 17 面、線上租借 9 面並非同一數字；部分面夜間不開放。不能寫成全場都可預約或整晚開放 |
| 台北網球中心／`taipei-tennis-center` | 有獨立場館規範，可呈現室內／室外差異 | 本輪室外頁已讀全文；室外開放時間與全館時間不同。室內詳情、交通及各費率仍需完整逐欄查核 |

### 頁面與入口

- `/courts/`：3 張指南卡，顯示名稱、區域及簡短用途說明。
- `/courts/youth-park/` 等：獨立、可直接重整與分享的指南網址；名稱、說明、來源與日期在初始 HTML 內，無 JS 仍可閱讀。
- 頁面順序：名稱／區域 → 訂場方式、開放時間與已核實設施 → 前往方式及官方入口 → 近期已定場球局 → 來源／最後查核日。
- 行動：「在這裡開球局」「管理球場訂閱」「查看近期球局」。官方入口依實際方式標示「官方場地資訊」或「官方預約說明」，不一律假稱可直接線上訂場。
- 站內入口：對應球場 sheet 增加「球場指南」文字連結；「我」頁資訊區增加「球場指南」索引連結。不調整首頁首屏版型或底部分頁。
- 沿用品牌色、字體與現有控制項；第一版以文字資訊為主，不使用未授權官方照片或 AI 假球場照片。

### 資料與互動

- 新增獨立 guide content 檔，引用 `data/courts.json` 的 slug／名稱／城市，不修改既有 seed 或硬編 DB ID。每項可變資訊記錄來源 URL、查核日與 verified／pending；查無資訊則省略或明確待確認。
- DB 現有 COURT_SELECT 沒有 slug：以目錄 canonical name＋台北市與 `loadCourts()` 的唯一結果解析 court ID；零筆或多筆時不猜 ID、不執行指定球場操作。建置檢查 slug 唯一及台北範圍；runtime 再驗 active catalogue。
- 靜態 generator 與 Vite 多入口整合；內容建置不向外部官方網站臨時抓資料，避免把來源暫停變成隨機 build 失敗。預覽設 noindex；正式 guide 設 title／description／canonical／OG，僅正式已發布指南進 sitemap。
- 球局互動程式依頁面載入，沿用 `src/dataApi.ts` 邊界新增精確球場查詢。查詢前先解析 court ID；伺服器端限制未來 14 天、單一球場或已定案候選、依 start_at／session_id 排序，取 4 筆顯示前 3 筆及是否更多。不要先截斷全城結果再用前端過濾。
- 第一版不列未定案候選局，標題明示「已定場」；full 可展示但清楚額滿。錯誤、載入中、沒有結果是三種狀態，不能將失敗呈現為 0 局。前景返回重新讀取，舊請求不得覆蓋新狀態。
- 「在這裡開球局」以 allowlisted court slug 的新入口接回 app。只保存 `create + courtSlug` 這種狹義意圖，登入／補個資後預選球場，其他欄位與發布仍由使用者填寫確認；取消／失效／切換帳號時按既有 intent 規則清除或重驗。不保存匿名完整草稿，因此不啟動 G08。

Vite dev／preview 不會自動模擬 Vercel Function：開發時新增可重用 handler 的本機 HTTP harness，且 CI 實際啟動它驗 raw HTTP；不能只 mock handler 後宣稱 server route 通過。Vercel preview 另驗 rewrite、模板打包、headers 與環境。第一個技術檢查點若證明現架構無法可靠封裝模板，先更新替代方案與影響，不擅自遷移整站框架。

必要檢查：`npm run test:ci:frontend`、`npm run test:local`、`npm run test:local:mobile`、適用的 production preview 測試與新 server／guide 行為測試。WebKit 依既有非阻擋政策保留結果。零 migration 可豁免 `test:db`，仍以匿名 view 真實 local API 測試驗新公開面；若後續發現需要 schema 變更，先更新規格與 scope。

容量沿用 2026-09-09 效能預算：Main raw 680 KB／gzip 200 KB；完整靜態入口 700／205 KB；本站匿名首訪 raw 820／encoded 260 KB；全部 JS 1 MB／gzip 300 KB；98% 提醒、release 超額阻擋。現有 lazy／Sentry／Push 邊界維持。新 guide entry 納入全站總量與自身靜態依賴報告，增加 guide 首訪量測與「不載 Maps」斷言，不藉多入口漏算。容量不過時先優化，不自動調高。

G10 server 套件／模板不算瀏覽器 JS，但另記 function bundle、回應大小、timeout 與 preview 延遲。原本手機 Maps LCP 問題保留為已知限制，不聲稱此批已修復。指南的主內容不等待 Maps 或即時球局請求，至少驗證慢網路下仍先有可讀 HTML。

部署仍以 git push 與既有 release checklist 留證據，不用 `vercel deploy`。G09 可撤下入口及靜態頁；G10 可回復分享產生器與 server 版本，已流通 `/s/:id` 至少保留通往舊 hash 的 fallback，避免 rollback 讓新連結永久失效。既有未提交效能預算與文件修改須保留、辨識後再組 commit，不能混同本輪程式成果。
