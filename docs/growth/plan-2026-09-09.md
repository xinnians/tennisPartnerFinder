## 目標

產品目標：讓使用者更容易第一次加入合適球局，讓主揪能輕鬆再開，進而形成重複打球。首要成果是每週回報打成且至少一位非主揪確認出席的真實球局數；這是回報代理指標，不宣稱現場驗證。

第一個工程里程碑：完成 G02 加入語意一致、G03 再次開局、G04 分享摘要，通過型別、靜態檢查、mock／本機整合與 production build，留下可重現證據。

原訂第一個營運里程碑（G01 已於 2026-09-09 暫緩）：準備 3–5 位主揪、一個球場群及 1–2 個時段的試點，記錄基準。既有模板保留，暫不啟動招募或事件追蹤；實際招募、社群訊息與試點時間由維護者安排。

成效觀察目標：先看至少 2 位非創辦人是否願意自主重開，再觀察完整 28 天窗的再次開局和再次打成。這是探索門檻，不是統計成功或產業標準。舊 MVP 最低活動門檻繼續保留：20 位真實使用者、8 個真實球局、3 次成功加入、至少 1 次打成回報。

## 執行原則

- 一次完成一個可驗證工作包，不把全部想法堆進同一批。遇到新證據可重排，記錄原因。
- 優先使用既有 view/RPC、加入矩陣、通知與表單，不擴大匿名個資欄位。
- 首批是純前端工作，不新增 migration，不變動正式站資料。
- 依 repo 規則執行 runtime 變更的 `npm run test:local`；不把 build 成功當作操作驗證。
- 部署另按既有 release checklist 留證據；沒有部署不得標為已上線。
- 計畫是依賴順序，四週試點是建議觀察設計，未宣告已啟動排程或自動化。

## 進度維護

每個工作項目分別記錄「規格、程式、本機 QA、部署、成效」。狀態可用待辦／進行中／完成／待外部資料；有依賴不等於整個專案停止。每次接續先查工作區差異，避免覆蓋其他 session。
