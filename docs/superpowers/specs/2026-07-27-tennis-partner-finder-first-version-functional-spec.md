# Tennis Partner Finder

## 第一版功能规格与验证方向

### 产品定位

帮助不依赖球团、俱乐部或既有熟人圈的网球玩家，更快找到合适球友，把时间、地点与人快速凑成一场球。

- 服务独立约球的个人使用者，不作为球团、俱乐部或会员体系的管理工具。
- 第一阶段覆盖台北与新北市，长期扩展至全台湾。
- 地图可显示双北所有球场；推广可优先从活跃球场或社群开始，但不限制其他地区使用。
- 公开地图只显示一般使用者可发现、可申请加入的球局，不承载球团内部局或会员专用局。

## 核心体验

1. 发起球局：使用者快速填写资讯并发布邀约。
2. 发现球局：从地图与清单找到附近、时间与程度合适的球局。
3. 加入确认：自动加入或经发起人审核；每位使用者只占一个名额。人数凑齐、参加者确认即视为成功成局。
4. 沟通开打：确认参加者进入球局专属群组，协调集合、费用与临时变动。

## 发起球局

### 必填资讯

- 时间：日期、开始时间与预计时长。
- 地点：从地图或球场清单选择；找不到时可落针新增地点，并标示为使用者新增。
- 想怎么打：单打、双打，或到场再决定；避免使用过于正式的「赛制」称呼。
- 人数：发起人自动算作第一位参加者，只需填写还缺几人；系统可依单打或双打建议人数。第一版不开放不限人数。
- 程度：NTRP 自评等级与可接受范围。

已订场必须有固定开始时间与时长；现场等场可填集合时间与预计时长，并可选择时间弹性；尚未决定场地则填日期、可打时间范围与预计时长。最终时间与地点由发起人在群组讨论后确认。

### 选填资讯

- 已订场时的费用分摊或免费。
- 简短说明。
- 加入方式：自动加入或发起人审核。
- 其他偏好。

场地需标示为已订场、现场等场，或尚未决定场地。现场等场是第一版正式支持的球局类型：人满只代表球友已凑齐、约好集合，不保证已取得场地；不另设「场地已确认」的手动更新步骤。现场等场默认是公共免费球场，不显示场租；尚未决定场地的球局，待最终确认需要租借时才补上费用。

## 地图与球局发现

- 首页以地图为主，并搭配可上拉的球局清单。
- 图钉显示球局；清单用于比较时间、程度、赛制与缺额。
- 可筛选时间、距离、NTRP、单打／双打和场地状态。
- 默认优先显示近期、距离近且程度相近的球局；使用者可自行放宽条件。
- 配对优先推荐 NTRP 相差不超过 0.5 的球局。

### 即时在场球友

第一版暂不做完全自动的在场定位。先用开放球局和短时效的「我现在想打」状态验证即时需求；当热门球场已具备使用密度后，再评估自动球场模式与背景定位。

球场资料应记录其使用模式，例如预约制、现场轮流制、两者并行，或资讯待确认；并可补充是否可能现场候补与使用备注。产品不替球团或俱乐部管理会员与场地使用权。

## 加入、聊天与通知

### 加入规则

- 发起人可选自动加入或审核加入；自动加入为预设，以支持快速凑局。
- 发起人先设可接受的 NTRP 范围，程度配对优先由这个条件处理；审核作为担心自评不准或需要额外确认时的例外保护。
- 审核只需通过或未通过，不要求填写拒绝原因；申请者收到中性结果通知即可。
- 加入前可看见发起人及已确认参加者的昵称、头像与 NTRP（若有填）；申请中资料只对申请者与发起人可见。
- 球局满人时只显示「名额已满」；第一版不做候补名单。

### 发起后的管理规则

- 发起人可编辑球局资讯、处理审核申请或取消整场；已有参加者时，时间、地点、场地状态、缺额、程度条件、费用与说明的变更都会通知参加者。
- 发起人可增加空位；若名额由满额变为有空位，地图与详情会重新开放加入。
- 发起人不得把总人数调低到已确认参加者人数以下，系统不会自动移除任何已核准的人。
- 第一版不提供发起人单独移除已确认参加者的功能；若球局无法继续，只能取消整场。

### 球局群组聊天

- 加入成功后自动进入该球局的临时群组。
- 第一版只需文字讯息、系统通知与参加者名单。
- 群组顶部固定显示球局资讯卡；发起人变更时间或地点时，系统通知已参加者，参加者可自行留下或取消，不要求重新确认。
- 尚未决定场地的球局由发起人在群组讨论后确认最终时间与地点，并同步更新资讯卡。
- 球局结束后一段时间自动封存。
- 第一版不做完整陌生人私讯社群。

### 通知策略

即时提醒用于申请处理、有人加入或取消、球局满人或取消、群组新讯息与开打前提醒。

高度匹配且时间紧迫的新球局可即时推送；其他新局进入每日摘要。使用者可设定距离、可打时段、NTRP 与通知频率。

## 信任与安全

- 以现有的 Google 登入作为第一版主要登录方式；Google 的名称与头像可先带入，使用者可确认或修改昵称后直接进入地图。
- 个人资料：昵称、默认头像或自选照片、NTRP 与简短自介；NTRP 可先跳过，之后随时补填或修改。
- 不公开电话与住址。
- 提供封锁、检举、离开群组和取消参加。
- 检举先限制继续发局或加入并进入人工查看，不公开处罚结果。
- 参加者可随时取消，名额会立即释出；发起人取消整场时，已参加者立刻收到通知。
- 第一版不强制记录实际出席或放鸟，也不做取消扣分或处罚；先做好取消、候补与开打前提醒。
- 天气不另设雨天方案栏位；临时状况由群组沟通与既有取消流程处理。

## 第一阶段验证

### 核心假设

台北、新北的网球玩家会发起或加入符合时间、地点与程度条件的球局，并让球局达到所需人数。

### 成功定义

球局达到所需人数，且所有参加者皆为确认参加。实际是否开打不列为第一阶段的必填资料；日后可用非强制的一键轻问收集。

### 观察指标

- 发局人数与球局数量。
- 加入人数与成功成局率。
- 使用者是否再次发局或加入下一局。
- 各区域、球场、时段与 NTRP 区间的成局差异。

## 用户流程：从进入 App 到找到球局

### 第一次进入

1. 使用者以 Google 登录；名称与头像可带入，使用者确认或修改昵称后继续。
2. NTRP 可跳过，之后再补填。
3. App 说明位置权限用来显示附近球局与球场；使用者可允许定位，或手动选择台北／新北的区域。
4. 直接进入地图首页，不加入冗长教学。

### 地图与找局

1. 地图显示附近球场与公开球局图钉；下方有可上拉的球局清单。
2. 默认优先显示近期、距离近、时间合适的球局；已填 NTRP 时，也优先显示程度接近的局。
3. 筛选只保留时间、距离、单打／双打、NTRP 与场地状态。
4. 球局详情优先呈现时间、地点、场地状态、缺额、程度条件、费用、发起人与已确认参加者。
5. 没有合适球局时，提供调整筛选与发起球局两个明确动作。

### 加入与确认

1. 自动加入且有名额、符合 NTRP 条件时，使用者点「加入球局」后立刻成为已确认参加者。
2. 审核制球局，或 NTRP 未填而无法自动判断条件时，使用者改为「申请加入」；发起人只需通过或未通过。
3. 通过后，人数与参加者名单更新，使用者进入球局专属群组，并看到系统加入讯息。
4. 名额已满时，显示「名额已满」，不提供候补。

### 发起球局

1. 使用者从地图首页点「发起球局」，先选择已订场、现场等场或尚未决定场地。
2. 表单只显示该类型需要的地点与时间栏位，再填写想怎么打、还缺人数、NTRP 条件、加入方式与简短说明。
3. 发起人自动占一个名额；单打与双打由系统建议缺额，到场再决定则由发起人自行填写。
4. 发布前显示球局预览；确认发布后，球局立即出现在地图与清单，发起人进入球局群组。

### 群组沟通与变更

1. 已确认参加者进入球局专属群组；群组顶部固定显示时间、地点、场地状态、人数、费用与发起人。
2. 参加者用文字沟通集合、球、费用与临时变动；第一版不做完整社群或陌生人私讯。
3. 发起人更新时间或地点时，系统立即通知已参加者；参加者自行决定留下或取消，不需重新确认。
4. 球局结束后，群组自动封存，保留纪录但不能继续传讯息。

## 既有专案对照

### 可沿用

- Google 登录。
- 地图优先页面、球场目录与球局清单。
- 球局、参加者、满额保护、取消与通知的后端基础。
- Supabase 权限边界与自动化测试基础。

### 需要调整

- 公开范围从台北市扩为台北与新北市。
- 球局从单一已确定球场与固定时间，扩为三种场地类型、区域选择、时间范围与预计时长。
- NTRP 从个人资料必填改为可跳过的参考资料。
- 加入后由主揪与单一球友互看 LINE 的设计，改为已确认参加者名单与球局专属群组聊天。
- 加入前可见发起人与已确认参加者基本资料；申请中资料仍维持私密。
- 发起人编辑名额时，新增不得低于已确认人数的资料库规则。

### 延后或停用

- 即时球友定位、自动位置分享与球友目录。
- 出席确认、实际开打回报、评价、放鸟纪录与处罚。
- 候补名单、付款、分帐、退款与完整陌生人私讯社群。

### 调整顺序

1. 先修改球局资料模型与资料库规则。
2. 再修改建立、探索、加入、取消与编辑的流程。
3. 接着加入球局群组与参加者可见范围。
4. 最后调整地图、通知与页面细节，并以既有测试为基础补齐新版流程测试。
